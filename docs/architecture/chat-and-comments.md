# مرزبندی دادهٔ گفتگو و دیدگاه

## تصمیم

گفتگوها، پیام‌ها و دیدگاه‌ها روی **همان اتصال و سرور دیتابیس سامانه** نگهداری می‌شوند، اما در یک جدول مشترک قرار نمی‌گیرند.

- دیدگاه‌های تسک، محتوا، ایده و دارایی در جدول canonical مشترک `comments` با مرجع `subject_type` و `subject_id` قرار دارند.
- گفتگو و پیام در مدل‌ها/جدول‌های مستقل پیام‌رسانی نگهداری می‌شوند؛ زیرا عضویت گفتگو، ترتیب پیام، خوانده‌شدن، پین، ویرایش، پاسخ و ACL آن‌ها با دیدگاه متفاوت است.

## دلیل

یکی‌کردن فیزیکی `messages` و `comments` فقط به‌دلیل شباهت ظاهری متن، جدول پر از ستون‌های nullable و شرط‌های دسترسی پیچیده می‌سازد و خطر نشت پیام خصوصی در queryهای دیدگاه را بالا می‌برد. استفاده از همان دیتابیس، تراکنش، backup و عملیات یکپارچه را حفظ می‌کند؛ جداسازی جدول‌ها نیز مدل امنیت و چرخهٔ عمر هر حوزه را روشن نگه می‌دارد.

اگر در آینده گزارش یا جستجوی مشترک لازم باشد، یک read model یا query تجمیعی مجاز ساخته می‌شود؛ منبع canonical هر حوزه همچنان مستقل باقی می‌ماند.
