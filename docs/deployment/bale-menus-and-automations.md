# منوهای جدید بله و قواعد فرمان/متن

> نسخهٔ ساختار سازمانی جدید، تیم را با دپارتمان جایگزین می‌کند. پیش از استقرار نسخهٔ جدید، [راهنمای انتقال دپارتمان‌ها](departments-consolidation.md) را اجرا کنید؛ قراردادهای team در این سند تاریخی‌اند.

## امکانات این تغییر

- دکمهٔ عمومی «ورود به پنل تدبیر» دیگر به منوها اضافه نمی‌شود. لینک اختصاصی مشاهدهٔ تسک حفظ شده است؛ لینک ثبت فایل هم یک عملیات مشخص است، نه دکمهٔ عمومی ورود.
- منوی اصلی فقط «وظایف من»، «جلسات من»، «ثبت دارایی» و «پروفایل و تنظیمات» دارد؛ دکمهٔ بازگشت/لغو در آن نیست.
- دکمهٔ اعلان‌ها از منوی اصلی و پروفایل بات حذف شده است. این تغییر **ارسال اعلان‌ها را خاموش نمی‌کند**؛ ترجیح دریافت از تب بله در پروفایل سامانه قابل مدیریت است. callback قدیمی اعلان‌ها، کاربر را به منوی اصلی می‌برد.
- «لغو» فقط هنگام پیش‌نویس/تأیید (ثبت متن یا ردیف، ویرایش و وضعیت وظیفه، قطع اتصال) دیده می‌شود. در فهرست‌ها و منوهای انتخاب، بازگشت کافی است. پس از ثبت موفق، لغو وجود ندارد.
- برای گرفتن کیبورد جدید `/start` بفرستید؛ پیام‌های تاریخیِ ارسال‌شده در بله به‌صورت دسته‌ای ویرایش نشده‌اند.

## سه مسیر ثبت دارایی

۱. **ثبت فایل:** بات لینک فرم امن فایل را می‌دهد. در حالت عمومی، `?dam_entry=file` پس از ورود عادی به سایت، مخزن و فرم فایل موجود را باز می‌کند. برای تسک، لینک قبلی `?task=ID&asset=file` استفاده می‌شود. هیچ توکن یا مجوزی در URL نیست. لینک‌ها فقط راهبری‌اند؛ API دارایی دوباره مجوز را کنترل می‌کند. آپلود مستقیم فایلِ ارسالی داخل چت بله پشتیبانی نشده و هیچ API حدسی دریافت فایل اضافه نشده است.

۲. **ثبت متن:** عنوان ← متن ← پیش‌نمایش ← تأیید؛ ثبت با `DamService` در مخزن واقعی، به‌صورت محرمانه. حالت عمومی نیاز به انتخاب تسک ندارد؛ حالت تسک، اتصال به همان تسک را حفظ می‌کند. مجوز مشاهده/ثبت دارایی و در حالت تسک مسئولیت جاری، دوباره هنگام ثبت بررسی می‌شود.

۳. **اطلاعات جدول:** تیمِ عضو ← جدولِ متصل و قابل‌ویرایش ← ستون‌ها ← پیش‌نمایش ← تأیید. همان `DamTableAccess` و `DamTableRows` پنل استفاده می‌شوند؛ دپارتمان/نام جدول، جای اتصال تیم و مجوز واقعی را نمی‌گیرد.

## تعریف نمونهٔ `/revayat`

مسیر: **تنظیمات سامانه ← بخش ربات بله ← فرمان‌ها و پاسخ‌های خودکار**. دسترسی `settings.manage` لازم است.

1. در تنظیمات جدول «روایات»، تیم مجاز را به جدول متصل کنید.
2. «افزودن قاعده» را بزنید؛ عنوان مدیریتی «ثبت روایت» و نوع محرک «فرمان با /» را انتخاب کنید.
3. فرمان `/revayat`، عملیات «افزودن ردیف به جدول مشخص»، جدول «روایات» و تیم متصل آن را انتخاب کنید.
4. قاعده را فعال و «ذخیره قواعد» را بزنید.
5. کاربر فعال و متصل که عضو همان تیم و دارای دسترسی ویرایش جدول است، `/revayat` را در گفت‌وگوی خصوصی بات بفرستد. فرم مستقیماً از اولین ستون شروع می‌شود؛ پس از دریافت ستون‌ها و تأیید، **یک ردیف** ایجاد می‌شود.

فرمان به‌تنهایی ردیف ناقص/خالی ایجاد نمی‌کند و نبود اطلاعات اجباری یا تأیید را دور نمی‌زند. هیچ جدول فرضی با نام «روایات» خودکار ساخته نشده و هیچ شناسه‌ای در کد hardcode نشده است.

برای مثال پاسخ خودکار: نوع «متن دقیق»، محرک «سلام»، عملیات «ارسال پاسخ متنی»، پاسخ دلخواه، فعال و ذخیره. فقط پیام کامل منطبق اجرا می‌شود؛ «سلام به همه» همان «سلام» نیست.

## عملیات قابل انتخاب

- پاسخ متنی ثابت و ساده؛ بدون اجرای template، HTML یا کد.
- شروع فرم یک جدول مشخص و تیم مشخص.
- شروع ثبت متن عمومی یا مسیر فرم فایل.
- بازکردن منوی دارایی، وظایف خود کاربر یا جلسات مجاز او.

ایجاد/ویرایش/حذف/فعال‌سازی/غیرفعال‌سازی قواعد در همان رابط انجام می‌شود. عمل دلخواه PHP، SQL، callback خام، URL دلخواه، regex، شرط contains و آرگومان فرمان اجرا نمی‌شود. افزودن عملیات جدید در آینده باید با سرویس دامنه و ACL خودش انجام شود، نه اجرای کد مدیر در بات.

## تطبیق و ایمنی

- سقف ۴۰ قاعده، محرک یکتا، حداکثر ۲۰ اجرای محرک در دقیقه برای هر اتصال. فرمان: `/` سپس حرف انگلیسی و حداکثر ۳۲ حرف/رقم/underscore؛ بدون آرگومان.
- متن پس از trim، یکسان‌کردن فاصله‌ها، کوچک‌کردن حروف انگلیسی و یکسان‌کردن `ي/ی` و `ك/ک` تطبیق داده می‌شود. فرمان‌های `/start`، `/menu`، `/cancel` و `/help` برای قواعد رزرو هستند.
- داخل فرم فعال، متن جواب فیلد است، نه محرک خودکار. برای فرمان جدید ابتدا فرم را تکمیل یا `/cancel` ارسال کنید. `/start` و `/menu` نیز فرم را رها کرده و منوی اصلی را باز می‌کنند.
- فقط حساب متصل و فعال می‌تواند قاعده اجرا کند؛ حساب دیگر، تیم نامرتبط، کاربر مسدود یا فاقد مجوز از این طریق قدرت تازه نمی‌گیرد.
- فرم‌ها همان انقضای ۱۰ دقیقه‌ای و nonce تأیید/انتخاب موجود را دارند. ثبت با `UpdateProcessor` و inbox/outbox قبلی انجام می‌شود؛ دریافت دوبارهٔ همان update یا دوباره‌زدن تأیید رکورد تکراری نمی‌سازد.
- شناسه و fingerprint قاعده روی پیش‌نویس و پاسخ صف‌شده می‌ماند. تغییر، حذف یا خاموش‌کردن قاعده، ادامهٔ فرم/ارسال پاسخ قدیمی را متوقف می‌کند. مجوز کاربر و تیم/جدول نیز دوباره بررسی می‌شوند. metadata داخلی برای بله ارسال نمی‌شود.
- تغییر ساختار جدول در زمان تکمیل فرم، ثبت را با سیاست نسخهٔ همان سرویس رد می‌کند.
- تنظیمات با revision ذخیره می‌شوند؛ تغییر هم‌زمان مدیر دیگر پاسخ ۴۰۹ می‌دهد و نسخهٔ جدید بی‌صدا overwrite نمی‌شود. تغییرات ثبت فعالیت می‌شوند؛ متن قواعد/توکن در فعالیت ثبت نمی‌شود.

## ذخیره و انتشار

- endpoint جدید: `GET/PUT /api/v1/bale/settings/automations`، احراز هویت + حساب فعال + `settings.manage`؛ پاسخ `no-store` است.
- از `system_settings` موجود با کلید اختصاصی `bale_automations_private` استفاده می‌شود؛ در API عمومی تنظیمات در دسترس نیست. revision و rules ذخیره می‌شوند؛ `tables` فقط کاتالوگ انتخاب در پاسخ مدیر است و دادهٔ ردیف‌ها را ندارد.
- رمز/تنظیمات اتصال بات در کلید جداگانهٔ قبلی باقی می‌مانند. قواعد هنگام حذف اتصال بات عمداً باقی می‌مانند؛ برای پاک‌کردنشان خود قواعد را حذف و ذخیره کنید. ربات جدید تا اتصال دوبارهٔ کاربران دسترسی آن‌ها را ندارد.
- این تغییر migration تازه، Cron، SSH، بستهٔ production یا API خارجی تازه لازم ندارد. امکانات جدول به نصب قبلی `dam_data_table_team` نیاز دارند. اگر جدول–تیم نصب نیست، فهرست انتخاب خالی است و قاعدهٔ جدول تا تکمیل نصب قبلی قابل ثبت نیست؛ راهنمای تعمیر قبلی را پس از بکاپ بررسی کنید.
- بک‌اند **و** محتویات `frontend/dist/` را با هم منتشر کنید. `.env`، فایل‌های خصوصی و تنظیمات Webhook هاست را حفظ کنید. دکمهٔ ثبت فایل عمومی به build جدید برای بازشدن خودکار فرم نیاز دارد.
- Webhook/getUpdates و مدل امنیتی ورودی تغییر نکرده‌اند؛ دستورها از همان پردازشگر مشترک اجرا می‌شوند. هیچ استقرار یا تست زنده روی بله/هاست در این محیط انجام نشده است.

## تست پذیرش روی هاست

- `/start`: نبود چهار دکمهٔ حذف‌شده و وجود «ثبت دارایی».
- ثبت متن عمومی و ثبت متن تسک، پیش‌نمایش، انصراف، تأیید دوباره، و اتصال درست دارایی.
- فایل از لینک عمومی و لینک تسک: ورود به حساب، فرم آپلود، ثبت و مشاهده در مخزن.
- `/revayat`: کاربر عضو و مجاز موفق؛ غیرعضو رد؛ حذف عضویت/تغییر ستون پیش از تأیید مانع ثبت.
- پاسخ متن دقیق؛ عدم اجرا برای متن مشابه یا پاسخ فیلد داخل فرم.
- تغییر/خاموش‌کردن قاعده قبل از تأیید و پیش از ارسال pending؛ فرم/پاسخ قبلی متوقف شود.
- ذخیرهٔ هم‌زمان دو مدیر، نمایش خطای تعارض بدون ازدست‌رفتن draft محلی.

## نتیجهٔ اجرای محلی

- تست‌های جدید منو/اتوماسیون: **۱۷ تست / ۶۶ assertion، همگی موفق**.
- مجموعهٔ عادی بک‌اند، همراه اصلاحات ACL مرحلهٔ قبل: **۱۸۱ تست / ۸۵۳ assertion، همگی موفق**. پنج موردِ باز ممیزی امنیتی جداگانهٔ مرحلهٔ قبل موضوع این تغییر نیستند و بسته‌شده فرض نشده‌اند.
- TypeScript موفق؛ تست‌های Node **۱۲/۱۲ موفق**؛ Pint فایل‌های PHP این تغییر موفق.
- build production موفق (۲۶۹۰ ماژول)؛ هشدار قبلی حجم bundle همچنان وجود دارد. خروجی در `frontend/dist` حفظ شده است: `index-DBwVPFBx.js` و `index-DXW7sbRp.css` با `index.html` جدید.
- محیط تست PHP 8.5.10 WASM / PHPUnit 12.5.35 / SQLite حافظه‌ای و HTTP جعلی بله بوده است. تست زندهٔ مرورگر، MySQL چندپردازه، آپلود روی هاست و ارسال واقعی بله انجام نشده است. ابزارهای آزمون خارج از وابستگی‌های production نصب شدند.
- فرمان‌ها با تطبیق متن پیام اجرا می‌شوند؛ برای نمایش پیشنهادهای slash در برنامهٔ بله، API حدسیِ ثبت فرمان اضافه نشده است.
