# حساب‌های بدون ایمیل و حداقل رمز ۸ نویسه

## قرارداد فعلی

- حساب‌ها با نام کاربری وارد می‌شوند؛ ثبت‌نام، مدیریت کاربران، پروفایل، فهرست اعضا و جستجو به ایمیل وابسته نیستند. ایمیل ساختگی هم تولید نمی‌شود.
- مایگریشن پایهٔ `users` دیگر ستون‌های `email` و `email_verified_at` را نمی‌سازد؛ جدول `password_reset_tokens` نیز حذف شده است. مایگریشن افزودن آواتار به `username` ارجاع می‌دهد، نه ستون حذف‌شدهٔ ایمیل.
- مسیرهای عمومی `auth/forgot-password` و `auth/reset-password` حذف شده‌اند. فرم ارسال کد/لینک بازیابی حذف و با راهنمای تماس با مدیر جایگزین شده است. broker ایمیلی فریم‌ورک نیز غیرفعال است.
- مدیر یا شخص دارای مجوز لازم پس از احراز هویت صاحب حساب، از مدیریت کاربران رمز جدید تعیین می‌کند. ACL موجود همچنان سمت سرور اجرا می‌شود؛ کاربر عادی نمی‌تواند رمز دیگران را تغییر دهد. پیام موفقیت تغییر رمز پروفایل فقط پس از پاسخ موفق سرور نمایش داده می‌شود.
- حداقل رمز اولیهٔ سید از **۱۲ به ۸ نویسه** کاهش یافته است. فرم‌های ثبت‌نام و ایجاد/ویرایش حساب نیز حداقل ۸ نویسه و شرط موجود حرف و عدد دارند. سقف bcrypt برابر ۷۲ **بایت** است؛ حروف چندبایتی با تعداد نویسه متفاوت‌اند.
- حداقل طول در صفحهٔ تنظیمات اکنون مقدار ثابت و فقط‌خواندنی ۸ است، نه گزینه‌ای که بدون تغییر اعتبارسنجی سرور قابل تنظیم باشد.
- گزینه‌های اعلان ایمیلی و خلاصهٔ هفتگی ایمیلی حذف شده‌اند. اعلان‌های داخل برنامه و بله از این تغییر مستقل‌اند.
- `.env`ها دیگر `SEED_*_EMAIL` یا تنظیمات SMTP نمی‌خواهند. `MAIL_MAILER=array` در نمونه‌ها فقط ارسال زیرساخت mail فریم‌ورک را غیرفعال نگه می‌دارد. رمزهای اولیه همچنان خصوصی‌اند و هیچ رمز پیش‌فرض عمومی اضافه نشده است.

## بازسازی دیتابیس طبق درخواست مالک

این نسخه عمداً **مایگریشن‌های پایه** را برای دیتابیس تازه/بازسازی‌شده اصلاح می‌کند. مایگریشن موقت حفظ ایمیل قدیمی کنار گذاشته شده است. اجرای معمولی `migrate` روی نصب از قبل مهاجرت‌کرده، ستون‌های قدیمی را حذف نمی‌کند؛ این نسخه مسیر ارتقای درجا برای دیتابیس قدیمی نیست.

**هشدار: `migrate:fresh` همهٔ جدول‌ها و داده‌های اتصال انتخاب‌شده را حذف می‌کند؛ نه فقط ایمیل‌ها.** قبل از اجرا اتصال DB را بررسی و از هر دادهٔ موردنیاز پشتیبان بگیرید. این دستور در کار حاضر روی دیتابیس کاربر/تولید اجرا نشده است.

برای محیط محلی دارای CLI، فقط پس از تصمیم صریح به بازسازی دیتابیس:

1. `.env` واقعی کنار `artisan` را حفظ کنید؛ `APP_KEY` موجود را تغییر ندهید.
2. سه متغیر `SEED_MAHDI_PASSWORD`، `SEED_EMAD_PASSWORD` و `SEED_AMIRALI_PASSWORD` را خصوصی و با حداقل ۸ نویسه تنظیم کنید. رمزهای نمونهٔ آزمون را استفاده نکنید.
3. در پوشهٔ `backend`، بعد از پشتیبان‌گیری و بررسی اتصال:

```bash
php artisan config:clear
php artisan migrate:fresh --seed
```

سید فقط سه حساب اولیه، نقش‌ها و مجوزهای پایه را می‌سازد؛ اطلاعات قبلی را برنمی‌گرداند. اجرای دوبارهٔ **خود سید بدون fresh** همچنان حساب موجود با همان نام کاربری را حفظ می‌کند.

هاست اعلام‌شده SSH/Cron ندارد. دستورات بالا راه اجرای خودکار روی آن هاست نیستند؛ بازسازی/انتقال دیتابیس باید با ابزار امن کنترل‌پنل و پشتیبانی هاست هماهنگ شود. هیچ endpoint عمومی اجرای migration یا seed ساخته نشده و استقرار تولید انجام نشده است.

## آزمون‌ها

پوشش `UsernameAccountsTest` شامل نبود ستون‌های ایمیل و جدول توکن، ثبت‌نام و ساخت چند حساب بدون ایمیل، پذیرش رمز ۸ و رد رمز ۷ نویسه‌ای، سقف ۷۲ بایت، الزام رمز هنگام ایجاد حساب، ACL تغییر رمز دیگران، ورود با نام کاربری، حذف مسیرهای بازیابی و حذف تنظیمات ایمیلی است. `InitialSeedTest` نیز ساخت بدون ایمیل و حفظ رفتار تکرارپذیر سید را بررسی می‌کند.

آزمون‌های مرورگر با API کنترل‌شده اجرا می‌شوند و جای آزمون اتصال واقعی به MySQL/هاست را نمی‌گیرند. **نتیجهٔ این نوبت:** بک‌اند ۲۷۲ تست / ۱۶۲۸ assertion موفق روی PHP-WASM 8.5.10 و SQLite؛ ۳۴ تست Node و ۳۶ تست مرورگر با API کنترل‌شده موفق؛ TypeScript و build تولید موفق. هشدار قدیمی اندازهٔ chunk باقی است. MySQL و هاست واقعی در این محیط آزموده نشده‌اند.
