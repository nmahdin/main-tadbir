## API، مسیر و migration

- مسیرهای UI: `/dashboard`، `/projects`، `/tasks`، `/contents`، صفحهٔ ID مستقل هر سه، `/approvals`، `/notifications` و مسیرهای موجود مدیریت. preview و `returnTo` زمینهٔ فهرست را حفظ می‌کنند؛ لینک مستقیم تسک حذف نشده است.
- فرمان بررسی: `POST /api/v1/contents/{content}/stages/{stage}/decision`؛ نسخهٔ دیده‌شدهٔ کاربر باید ارسال شود، نه نسخه‌ای تازه که بدون مرور کاربر گرفته شده است.
- بازیابی: `POST /api/v1/{projects|tasks|contents}/{id}/restore`.
- حذف metadata: `DELETE /api/v1/tasks/{task}/attachments/{attachment}`.
- جداکردن asset مشترک: `DELETE /api/v1/dam/library/{asset}/tasks/{task}`.
- `GET /api/v1/dam/data-tables/rows-by-task?task_id={task}` و library با فیلتر رابطه و pagination معتبر؛ مسیر دقیق در route inventory آمده است.
- mutation قالب و نقش از API موجود استفاده می‌کند؛ endpoint موازی ساخته نشده است.
- migration جدید `2026_09_29_000002_preserve_archive_and_review_cycles.php`: وضعیت قبل از آرشیو، parent/source lineage اصلاح، checklist و ایندکس صف بررسی. migrationهای قبلی دپارتمان/بله/انتشار و تعمیر SQLite نیز باید هماهنگ باشند. `down()` تاریخچه را تخریب نمی‌کند؛ rollback schema نیازمند backup هماهنگ و برنامهٔ جداگانه است.

CLI-WASM ممکن است حتی در شکست PHPUnit exit صفر بدهد؛ summary واقعی بررسی شد. workaround `mockConsoleOutput=false` فقط هنگام suite کامل اعمال و `tests/TestCase.php` بازگردانده شد. تست واقعی مرورگر به معنی MySQL یا هاست اشتراکی واقعی نیست؛ DB این اجرا SQLite ایزوله بود. یک شکست متناوب Escape در اجرای میانی پیدا و برطرف شد؛ آن اجرا موفق گزارش نشده است. سرور آزمایشی WASM در یک تکرار بعدی با خطای poll/accept بی‌پاسخ شد؛ پس از راه‌اندازی مجدد با همان DB ایزوله، هر پنج سناریوی واقعی مجدداً موفق شدند. این نیز دلیل دیگری برای الزام آزمون PHP بومی است.

## موانع واقعیِ باز

1. **API-first سراسری تمام نشده:** دو effect همگام‌سازی قدیمی در `AppContext.tsx` برای ایده/جلسه/نامه/مصوبه/پرونده و DAM/chat قدیمی باقی‌اند. ساخت conversation/نامه/مصوبه، حذف‌های قدیمی و تبدیل ایده به پروژه/تسک هنوز قرارداد یکسانِ await/حفظ draft/تأیید سرور ندارند. تنظیمات نیز draft + autosave قدیمی دارد. این‌ها خارج از فهرست بسته‌شدهٔ بالا هستند، نه عملیات تأییدشدهٔ جدید.
2. **ممیزی all-module و UI جامع باز است:** بعضی read scopeها، فرم‌ها، selectorهای محدود به ۱۰۰ و exceptionهای شخصی/دپارتمانی سایر ماژول‌ها باید با تست منفی مستقل بررسی شوند. پنج مجوز بدون reference literal در inventory به‌تنهایی نه اثبات آسیب‌پذیری‌اند و نه اثبات پوشش.
3. **Load و حجم:** صف بررسی و rows-by-task حافظه محدود اما اسکن خطی دارند؛ bundle اصلی و icon chunk هنوز بزرگ‌اند. نتیجهٔ بار واقعی نداریم.
4. **Gate محیط انتشار:** PHP بومی سازگار، MySQL/MariaDB روی کپی DB، migration، JSON/boolean/read-all، HTTPS/CORS/Sanctum بین دو دامنه، upload/download خصوصی، Apache rewrite و OPcache هاست باید تست شوند. دسترسی اجرای این موارد در این محیط فراهم نشد؛ نصب MariaDB نیز به محدودیت شبکه خورد.
5. **Legacy بدون سابقه:** وضعیت قبل از آرشیو رکوردهای قبلی و فایل‌های blob قدیمی را نمی‌توان حدس زد یا از نو ساخت. اصلاح داده نیازمند بررسی موردی مالک سامانه است.

به‌خاطر موارد ۱ و ۲، باقی‌مانده فقط «تست روی هاست» نیست؛ کار پیاده‌سازی نیز باقی است. این گزارش نباید به‌عنوان تأیید تکمیل صددرصد دو فاز یا اجازهٔ انتشار تولید استفاده شود.

## تحویل و انتشار بدون SSH/Cron

`frontend/dist/` خروجی build تولید است و همراه source در نسخه نگه داشته می‌شود؛ سورس را تغییر داده و دوباره build کنید، نه dist را دستی. `.htaccess` داخل artifact است. هیچ endpoint عمومی اجرای artisan، job تازهٔ Cron یا تغییر APP_KEY تولید اضافه نشده است.

پیش از انتشار: backup کد/DB/فایل‌های خصوصی و env موجود؛ اجرای migration و آزمون‌ها روی کپی DB از دستگاه توسعه/روش امن کنترل‌پنل؛ انتشار هماهنگ backend و تمام dist؛ حفظ کلید موجود؛ بررسی cookie/HTTPS و دو حساب مجاز/غیرمجاز؛ سپس smoke مسیر مستقیم، موبایل، approval conflict، restore، pagination و فایل. راهنمای جزئی: [deployment.md](deployment.md). اجرای build یا موفقیت تست محلی معادل استقرار نیست.
