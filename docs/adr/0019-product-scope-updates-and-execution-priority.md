# ADR-0019 — Product-scope updates, module catalog v1.4, and execution priority

**Status:** ACCEPTED (product-owner instruction, 2026-10-19; documentation/planning decision — authorizes no implementation). Code baseline `bc6cf891` on `arena/582a70e5-main-tadbir`; PR #14 OPEN and UNMERGED by instruction.

## Context (CONFIRMED)
UX-02-3-FINAL was delivered at `bc6cf891` with all five product CI gates green, but **has not received human Laragon acceptance**; green gates do not replace approved-decision compliance. The product owner issued catalog updates and a binding package execution order. This ADR records them in the decision register so future packages trace to approved decisions rather than improvisation.

## Decisions
1. **Product Management is a FUTURE module** (`product-management`), separate from Projects. Proposed scope: product roadmaps, features, releases, feedback, lifecycle management. Recorded in `docs/architecture/product-and-module-catalog.md` §3/§4/§6 (disposition 5, ID reservation only).
2. **Commerce / E-commerce / Store remains exactly one FUTURE entry** (`commerce`). No duplicate store module may be created.
3. **The `notes` module's architectural scope is expanded** into a comprehensive OneNote/Notion-inspired notebook and knowledge workspace. Candidate capabilities (notebooks, sections, nested pages, block editing, autosave, search, attachments, cross-links, version history, permission-aware collaboration) are **design candidates requiring a dedicated Notes specification stage**; they are not authorized for implementation by this decision.
4. **Catalog counts:** 22 registered main modules (16 reusable + 6 specialized) unchanged; future development areas increase 14 → **15**.
5. **Execution priority is binding** (master roadmap: `docs/roadmap/tadbir-comprehensive-master-roadmap.md`): (1) UX-02-3-FINAL Laragon acceptance/fixes → (2) UX-02-4 → (3) AUTH-EXT-01 → (4) C5-EXT-01 + subscription checkout → (5) UX-03 → (6) WEB-CMS-01 → (7) CORE-REQ-01 + SYS-MSG-01 → (8) SUP-01 → (9) OPS-01 → (10) BACKUP-01 + MAINT-01 → (11) UX-04 → (12) business modules in separately approved priority order. UX-01 advanced layout customization stays deferred until module pages stabilize. Reordering requires a explained technical-dependency justification before execution.
6. **No package starts without explicit user authorization.** In particular UX-02-4, UX-03, WEB-CMS-01, Notes, Product Management, and E-commerce must not be started. PR #14 stays open and unmerged; no force-push, production deployment, or database reset; the Windows/Laragon MariaDB 10.4.32 `tadbir` database is preserved; no destructive migrations.
7. **Every future implementation package ships a traceability matrix**: approved decision ID and behavior → exact UI pages/sidebars/navigation → DB/API changes → authorization and environment rules → implementation files → tests and visual evidence → status (implemented / partially implemented / deferred / blocked). Passing tests alone never mark approved UX functionality complete.
8. **Preserved approved exceptions/refinements** (binding on all packages): no recent environments in the environment selector; large concise environment-selection button cards; separate Ocean-compatible sidebars per context; Persian-only public website and CMS (no multilingual infrastructure); independent `/site-studio` interface; no mandatory multi-person CMS publication approval in the CMS MVP; OPS detail retention six months with twelve months of aggregates; four-level backup scopes (platform, organization, workspace, personal); global and scoped maintenance with backend enforcement.
9. **Outstanding gates stay open** until genuinely satisfied: UX-02-3-FINAL human Laragon acceptance; independent security scan (a neutral/skipped scanner result is not a pass); ARCH-02 local Laragon acceptance. Nothing in this ADR closes them.

## Consequences
The catalog (v1.4) and master roadmap are the authoritative planning references; later packages (AUTH-EXT-01, C5-EXT-01, CORE-REQ-01, SYS-MSG-01, SUP-01, BACKUP-01, MAINT-01, UX-04, Notes expansion, Product Management, Commerce) each need an implementation-ready specification stage before code. Implementation resumes only on explicit authorization, starting from UX-02-3-FINAL acceptance feedback.
